Dynamic Agent Management Platform

แพลตฟอร์มที่ให้ผู้ใช้พิมพ์คำสั่ง → AI ประเมินและสร้างแผน → ผู้ใช้อนุมัติ → AI Agent หลายตัวทำงานร่วมกัน → ส่งผลลัพธ์กลับ

💬

ผู้ใช้พิมพ์คำสั่ง

พิมพ์ว่าต้องการอะไร เช่น "วิเคราะห์สินค้า X เปรียบเทียบคู่แข่ง" ระบบจะประเมินว่าต้องทำอะไรบ้าง

📋

AI สร้างแผน

AI ออกแบบ Agent ที่จำเป็น พร้อมเครื่องมือและโมเดล แสดงเป็น "แผน" ให้ผู้ใช้อนุมัติ

🤖

Agent ทำงาน

หลังอนุมัติ Agent ทำงานพร้อมกัน (CrewAI) มี Manager คุม ส่งผลลัพธ์เรียลไทม์

🎯 ฟีเจอร์หลัก

✓ สร้าง Agent อัตโนมัติจากคำขอ
✓ เลือกโมเดล AI ที่เหมาะสมให้แต่ละ Agent
✓ เครื่องมือ: ค้นเว็บ, สร้างรูป, สร้างวิดีโอ, อ่านไฟล์, สร้างเสียง
✓ ความคืบหน้าเรียลไทม์ผ่าน WebSocket
✓ ระบบ Review: Manager ตรวจสอบคุณภาพ
✓ อนุมัติการสร้างสื่อก่อนให้ AI ทำ
✓ จัดการทีม Agent: สร้าง, แก้ไข, ลบ, ใช้ซ้ำ
✓ ประวัติแชท + ประวัติ Task
✓ ทำงานตามเวลา (Schedule)
✓ รองรับไฟล์แนบ: รูป, PDF, เสียง, วิดีโอ, URL
✓ คำนวณค่าใช้จ่าย (Credits)
✓ ล็อกอินผ่าน System81 OAuth

🖥️ Frontend

  • React + TypeScript + TailwindCSS
  • Vite dev server (port 5173)
  • 2 UI: Modern + Retro Win95
  • สื่อสารผ่าน WebSocket
  • 45 ไฟล์, ~15,600 บรรทัด

⚙️ Backend

  • Python + Chainlit (port 8000)
  • CrewAI multi-agent engine
  • JSON file persistence (ไม่มี DB)
  • OpenRouter API สำหรับ LLM
  • 54 ไฟล์, ~13,900 บรรทัด

🌐 External

  • OpenRouter: LLM API
  • System81: OAuth login
  • Playwright: headless browser

State Machine — สถานะของ Task

Task เปลี่ยนสถานะยังไงตั้งแต่เริ่มจนจบ

stateDiagram-v2 [*] --> pending: ผู้ใช้ส่งคำขอ pending --> planning: Secretary ประเมิน planning --> awaiting_approval: ส่งแผนให้ผู้ใช้ awaiting_approval --> approved: ผู้ใช้กด Accept awaiting_approval --> rejected: ผู้ใช้กด Reject awaiting_approval --> revised: ผู้ใช้แก้ไข revised --> awaiting_approval: ส่งแผนใหม่ approved --> running: Orchestrator เริ่ม rejected --> [*] running --> awaiting_media: Agent ขอสร้างสื่อ awaiting_media --> running: ผู้ใช้อนุมัติสื่อ awaiting_media --> running: ผู้ใช้ปฏิเสธ (ข้าม) running --> reviewing: Manager ตรวจงาน reviewing --> completed: ผ่าน reviewing --> running: ไม่ผ่าน (ทำใหม่) completed --> [*] running --> failed: เกิด error failed --> [*]

📊 สถานะหลัก

  • pending — รอให้ Secretary ประเมิน
  • planning — Secretary กำลังวิเคราะห์
  • awaiting_approval — รอผู้ใช้อนุมัติแผน
  • approved — ผู้ใช้อนุมัติแล้ว
  • running — Agent กำลังทำงาน
  • reviewing — Manager กำลังตรวจ
  • completed — เสร็จและผ่านการตรวจ
  • failed — เกิด error ระหว่างทำงาน
  • rejected — ผู้ใช้ปฏิเสธแผน

🔄 สถานะ Agent

  • idle — ยังไม่ได้ทำงาน
  • working — กำลังทำ Task
  • waiting — รอสื่ออนุมัติ
  • done — ทำเสร็จแล้ว
  • error — เกิดปัญหา

💾 การเก็บ State

State ทั้งหมดเก็บใน cl.user_session (Chainlit) — เป็น dict ไม่มี type safety และเก็บใน JSON files ผ่าน TaskStore

✅ พื้นฐาน

รู้ว่าโปรเจคคือแพลตฟอร์มสร้าง AI Agent อัตโนมัติ
รู้ว่ามี 2 UI: Modern และ Retro Win95
รู้ว่า Frontend สื่อสารกับ Backend ผ่าน WebSocket
รู้ว่า Backend ใช้ Chainlit + CrewAI
รู้ว่าไม่มี database — เก็บใน JSON files
รู้ว่า LLM มาจาก OpenRouter API
รู้ว่าล็อกอินผ่าน System81 OAuth

✅ Data Flow

รู้ว่าผู้ใช้พิมพ์ → Secretary ประเมิน → สร้างแผน → อนุมัติ → Agent ทำงาน
รู้ว่า Secretary แยกได้ว่าเป็น chat / ask / plan
รู้ว่า Orchestrator สร้าง CrewAI Crew และสั่ง Agent
รู้ว่า Messenger ส่งข้อความ BE↔FE ผ่าน WebSocket
รู้ว่ามีระบบ Review: Manager ตรวจงานก่อนส่งมอบ
รู้ว่ามีระบบอนุมัติสื่อ (รูป/วิดีโอ) ก่อนสร้าง

✅ โมดูลหลัก

รู้ว่า chat.py (3141 บรรทัด) เป็นไฟล์ใหญ่สุด รับทุก message
รู้ว่า actions.py มี 19 action handlers (accept, reject, edit, ฯลฯ)
รู้ว่า LLM Manager มี fallback + rotator (สลับโมเดล)
รู้ว่า Tools มี 6 ตัว: search, media, audio, browser, document, web
รู้ว่า Attachment Processor จัดการไฟล์+URL พร้อม SSRF protection
รู้ว่า Scheduler รัน task ตามเวลา (daily/weekly/monthly)
